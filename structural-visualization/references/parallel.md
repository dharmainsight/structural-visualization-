# 並列化思考 — 操作規則

出典: S01-1・S01-2（第1章の指定箇所と第2章の基本・5要件）。以下は原典の着想を一般的な情報構造化へ転用する独自設計。原典との対応は sources.md を参照。実用性は未検証。

## 1. 分類の設計

入力: 対象範囲 U、読者が答えたい問い Q、対象の属性・関係・根拠。
出力: 共通基準で整理された要素群、必要に応じて根拠・未分類・重複・表示方法。

- 事実由来: 制度、観測、慣習などの既知の区分を用いる。対象の時点、地域、定義、範囲を確認する。慣習上の区分を自然法則と混同しない。
- 法則由来: 定義、式、理論、明示された規則から要素を抽出する。成立条件を確認し、式の変数・相互依存と部分集合への分割・加算的分解を区別する。
- 目的由来: 事実や法則で基準が決まらない場合、問いに照らして比較可能な分類軸を設計する。複数案が成立し得ることを認め、必要なら代案・反例を比較する。

二項対立を使う場合も、両項の境界・中間・未判定・両立可能性を検証する。3項目以上の目的依存分類では基準を明示して反例で検証する。要素数そのものから妥当性は推定しない。

## 2. 論理的検証

- 対象範囲と基準を先に定める。同一階層で異なる抽象度・属性・観点を混在させない。
- 排他的な分類を意図する場合だけ、MECE（Mutually Exclusive, Collectively Exhaustive：相互排他・全体網羅）を要求する。集合分割では、各対象の所属が一意であり、分類群の和集合が定義した全体 U と一致するか確認する。
- 重複が意味を持つタグ、観点一覧、式の変数等に排他的分割を強制しない。重複可能・非加算的な場合は明示する。
- 網羅性の範囲を宣言する。完全性が確認できない場合は「主要項目」「暫定分類」「未調査」「その他」等を適切に使用する。既知の反例を隠さない。
- 追加・統合・分割で理解目的を満たすか検討し、必要なら別軸または階層化に移る。

## 3. 伝達の最適化

| 原典の着想 | 実装規則 |
|---|---|
| 有用性 | 読者の判断・説明・行動に使える区分を優先する |
| 図示可能性 | 意味関係を強調する図・表だけを選ぶ。図による完全性の錯覚を避ける |
| 記憶しやすさ | 用語の品詞・語の粒度・形式を揃える。語呂や略称のために意味を変えない |
| 権威づけ | 出典、標準、採用理由を示す。権威や普及度と論理的妥当性を区別し、架空の典拠を作らない |
| 認知負荷 | 要点は3〜5程度を初期目安とする。必要な項目数を優先し、意味のあるチャンク化・階層化・詳細表で情報を保持する |

これらは伝達の設計指針であり、論理的完全性の十分条件ではない。5項目前後という著者の経験則を厳格な認知上限にしない。

## 4. 表現選択

- 同列の対象は同程度の視覚的重み・書式を割り当てる。大小・順序・色で根拠のない優劣を表さない。
- 属性を揃えて比較する必要があるときは表、独立項目の短い説明には箇条書き、共通のまとまりを示す場合にグループ化を使う。
- 依存関係が主目的なら時系列・ネットワーク、親子関係なら階層、2軸の位置なら二次元を併用または選び直す。
- 分類項目と実際の項目数を混同しない。必要なら概要と詳細を分け、情報を切り捨てない。

## 5. 自作例

- 12個の監査項目を、アクセス管理・記録・復旧などの実質的なまとまりで整理し、詳細12項目を保持する。上位分類の完全性は監査範囲で確認する。
- 複数の購買理由をタグ付けする場合、1人が複数の理由を持つことを許容する。タグの比率を排他的な内訳として表示しない。
- 既存の有名な分類に当てはまらない事例は、その分類の適用範囲または追加軸の必要性を検討する材料にする。
