# 包含と分解

入力: 読者の問い、対象群、関係の根拠、整理する範囲。
出力: 関係型を保った水準と親子関係、同水準のまとまり、共有・省略・未確定事項。

## 1. 親子の意味を定める

語の対比だけで上下を決めない。同水準の違い、包含・構成、目的の具体化、過程の前後を区別する。見た目が同じ木でも、次の関係は異なる。

| 関係型 | 確認すること |
|---|---|
| 型と下位型 | 下位型の定義が上位型の範囲に含まれるか |
| 全体と構成部分 | 実際の構成要素か。共有、重複、加算可能性はどう扱うか |
| 問題と原因候補 | 観測、作用の仕組み、反例、共通原因、相互作用が仮説をどこまで支えるか |
| 目的と実現手段 | 手段がどの条件で目的に寄与するか。代替・併用・制約は何か |
| 主張と根拠 | 根拠が支持する範囲と条件は何か。反証や不足は残っていないか |

原因候補、手段、論拠を、構成部分や確定した因果関係と同一視しない。関係型が変わる箇所は見出しや辺のラベルで示す。

## 2. 必要な水準へ分ける

1. 整理する全体と範囲を定める。共通の親が不明なら複数のまとまりから始める。
2. 同じ親の直下では、観点と相当する粒度を揃える。重要度、名称、語の長さから水準を推定しない。
3. 各親子関係の成立を確認し、次に兄弟項目の範囲・粒度・重複を確認する。縦と横を別々に点検する。
4. 網羅的な分解なら親の範囲に対する欠落を確認する。重点の抜粋なら選択範囲を明示し、体系全体とは呼ばない。
5. 排他的な構成分解では、各親の直下だけでなく最終項目全体の二重計上も確認する。定量分解は演算、単位、分母、粒度を照合する。
6. 不明な中間項目を補作しない。省略した既知の項目と未確認の項目を区別する。

原因、対策、根拠には重複や共同成立があり得る。すべて必要な組合せと、いずれかで足りる代替を、裏付けのある範囲で区別する。必要性や十分性が不明なら断定しない。

## 3. 木の制約を確認する

- 根付き木では、根以外の各項目の親は一つで、循環がないことを確認する。
- 複数親や共有部分がある場合は、同じ対象IDを保ち、対応表、参照、循環のない有向関係図などを使う。見やすさのための再掲は同一対象と明示する。
- 循環する依存を木に強制しない。関係図へ切り替え、戻りや相互作用を残す。
- 親子の表示方向と因果の作用方向を区別する。「問題から原因を探す」読み順を「問題が原因を生む」矢印にしない。

## 4. 分析と説明を組み立てる

- 構成を調べるときは、何が含まれるかを分解する。診断するときは、原因仮説と検証結果を対応づける。
- 対策を選ぶときは、対象課題、実行条件、担当、期待効果、副作用を整理する。原因候補から対策の有効性を自動的に導かない。
- 主張を説明するときは、結論、支持する理由、判断を変え得る反証・条件を対応づける。結論を先に提示するために証拠を選別しない。
- 新しい証拠が初期仮説に反する場合は、上位の結論を更新する。
- 分析する順序と、説明で提示する順序を分ける。分析は仮説・検証・結論更新を往復する。結果の説明では現在の結論、支持・反証と成立条件、必要な調査経緯の順を基本とする。経緯そのものが問いの場合は時系列で示す。

## 5. 表現と停止条件

短い体系には入れ子一覧、分岐の把握にはツリー、属性や根拠の比較には表を使う。二水準で足りればそこで止め、全枝の深さや分岐数を揃えるために項目を増やさない。

分解は、読者の判断・実行・追加調査に必要な単位まで行う。下位へ進んでも判断が変わらない、観測根拠がなくなる、単なる言い換えになる場合は止める。深さを重要度とみなさない。

## 6. 適用例

- 予算の構成では金額の合計と重複を確認する。障害原因の整理では証拠と相互作用を確認する。同じ検査で済ませない。
- 一つの機能が検索と分析の両カテゴリに属する場合は、両方との対応を残し、機能数は対象IDで数える。
- 全体目標、科目ごとの目標、個別課題は、何に寄与するかを確認して水準を分ける。対応が不明な課題は「対応未確認」と記し、確認済みの「対応なし」と区別する。
- 導入提案では利点と費用の両方を根拠に対応づけ、採用条件が満たされない場合の判断も示す。
