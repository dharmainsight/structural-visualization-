# 階層化思考 — 基本操作規則

出典: S01-1・S01-3a。以下は提示資料の着想から導く独自実装（PROPOSAL）。ロジックツリーとピラミッド構造の原典説明（S01-3b）は未確認。実用性未検証。

## 1. 関係を識別する

入力: 問い Q、対象群、関係の根拠、体系化する範囲。
出力: 水準、親子関係、同水準のまとまり、未確定事項、最小の表現。

- 同じ観点・水準での違いなら並列化を候補とする。
- 包含・構成・抽象度・目的から手段への具体化などの水準差が主題なら階層化を候補とする。
- 過程の順序や状態遷移が主題なら時系列化を候補とする。
- 対語であることだけを排他性、網羅性、優劣、時間的先後、因果の根拠としない。複数の関係が成立するなら問いに必要な関係を選び、必要に応じて補助構造を用いる。

## 2. 設計と検証

1. 何の体系か、根・対象範囲・読者の問いを定義する。根が不明なら無理に単一の根を置かない。
2. 親子の関係型を定義する（下表）。異なる関係型を混ぜるなら辺や階層の見出しで区別する。
3. 同じ親の子を同じ観点と相当する粒度で整理する。水準は語の長さ、重要度、見た目、組織名称だけから推定しない。深さと重要度は別である。
4. 体系の網羅を意図するときだけ親の範囲に対する子の不足を検証する。排他的分割なら並列化のMECE検証を適用する。重点だけを選んだ資料は選択範囲を明示し、未提示部分を捏造しない。
5. 水準混在があれば関係の根拠を確認して再配置する。不明な中間項目は省略・未確認として示し、架空の親を作らない。
6. 根付き木では各非根ノードの親は一つで循環がない。複数親を持つ分類や共有部品では、有向非巡回グラフ、参照、表などを使う。循環がある依存関係は別構造として扱う。

| 関係型（独自区分） | 検証条件 |
|---|---|
| 型と下位型 | 下位型の定義が上位型の範囲に含まれるか |
| 全体と構成部分 | 部分が全体の構成要素か。共有・重複・加算可能性を別に確認する |
| 方針と実現手段 | 手段が方針にどう寄与するか。必要十分性・因果効果を無根拠に断定しない |
| 主張と根拠 | 根拠がどの条件で主張を支持するか。関連性と証明の十分性を区別する |

一律に集合包含や加算的分解とみなさない。

## 3. 表現

- 2水準でも階層とみなせる。必要な深さだけを選び、均一な深さ・分岐数は要求しない。
- 短い体系なら入れ子一覧、分岐の把握が重要ならツリー、同階層の属性比較には表を選ぶ。関係型や水準が見た目だけで分からなければラベルを付ける。
- 同階層に置かれたことだけで因果・同時性・排他性を含意しない。矢印の向きは実際の関係に合わせる。
- 部分的な表示では省略・未調査・重点項目を区別する。

## 4. 自作例

- 学習プログラムの目的、科目の到達目標、個別課題を同列の柱とせず、何に寄与するかを確認して水準を分ける。重点の抜粋なら網羅的な体系とは呼ばない。
- 一つのソフトウェア機能が複数カテゴリに属する場合、親を一つに偽装せず多重所属を示す。
- 「設計と実装」を工程として問うなら順序、役割比較なら並列を検討する。順序だけから必然的な因果を作らない。

後続節の確認後にロジックツリーの種別、分解と論証の違い、トップダウン・ボトムアップの操作規則を再検討する。
