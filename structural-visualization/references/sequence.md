# 順序と依存

入力: 読者の問い、対象範囲、出来事・活動・状態、時点・条件・依存とその根拠。
出力: 根拠のある順序、分岐・並行・合流、実績・予定・不明の区別。診断なら課題・対策・検証の対応。

## 1. 何を読むための順序か決める

| 目的 | 整理するもの |
|---|---|
| 経緯を知る | 出来事、実時刻、期間 |
| 実行手順を知る | 活動、入力・出力、開始・完了条件、依存 |
| 状態の変化を知る | 状態、遷移条件、可能な次の状態 |
| 現状を診断する | 適用可能な参照工程と現状の対応、差異の根拠 |
| 計画する | 提案する活動、担当、条件、予定と不確実性 |

時間的前後、実行上の依存、状態遷移、因果を区別する。先に起きたことだけで原因とはしない。入力が単なる役割比較なら順序を補わない。

## 2. 工程と接続を定める

1. 開始・終了の範囲と観測単位を定め、問いに必要な粒度で工程を切り出す。
2. 必要な属性だけを持たせる。候補は工程ID、活動、担当、入力・出力、開始・完了条件、依存先、時刻・期間、状態、根拠とする。
3. 必須の前後関係だけをつなぐ。並行、任意工程、条件分岐、再試行、重なり、順序不明を保つ。
4. 合流では「すべて完了」「いずれか完了」などの条件を確認する。条件不明のまま任意の合流規則を作らない。
5. 予定、実績、推定を区別する。未観測の所要時間や架空の日付を追加しない。

日時のない手順図を比例時間軸にしない。担当を横に並べただけで同時実施とみなさない。再試行は同じ活動の次の実行であり、過去の時刻へ戻る矢印とはしない。

## 3. 参照と現状を照合する

規程、合意した目標、比較実績、仮説のどれを参照するかと、適用条件を確認する。未合意の標準案は案として示す。適切な参照がなければ現状の観測から始める。

同じ目的と粒度の工程を対応づける。変更、追加、欠落、分割・統合、順序違いを区別し、対応が不明ならそのまま示す。

| 状態 | 判定条件 |
|---|---|
| 充足 | 根拠により期待条件を満たす |
| 一部充足 | 条件の一部だけを満たす |
| 未充足 | 未実施または期待条件に反する根拠がある |
| 不明 | 判定に必要な観測がない |
| 非適用 | 分岐条件などにより対象外である |

実施の有無と成果の達成を分ける。記録がないことを未実施と断定しない。参照との差をすべて欠陥とせず、条件に合った省略や代替を認める。色・記号に加えて状態名と理由を示す。

## 4. 改善と検証を対応づける

- 不足、待ち、手戻り、品質低下がどの工程にあるかを、根拠とともに整理する。差異の存在だけで根本原因や律速工程を確定しない。
- 対策には対象工程、変更する行動・条件、担当、時点、期待出力、観測指標を必要に応じて対応づける。
- 局所の短縮が全体の短縮になるか、他工程へ負担を移さないかを確認する。効果は実施後の観測まで仮説として扱う。

## 5. 表現と停止条件

単純な順序は番号付き手順、実時刻や間隔はタイムライン、分岐・並行・依存は条件付きフロー、参照との差や対策の対応は表を使う。担当間の受渡しが主題なら担当別の区分を加える。

比較図では工程ID、粒度、範囲を揃える。次に何を行えるか、何を待つか、どの状態が不明かが読めれば、不要な工程の細分化を止める。

## 6. 適用例

- 書類審査と設備点検を独立に開始でき、両方の完了後に許可するなら、並行する二工程と合流条件を残す。
- 検品の未実施は確認済み、梱包は記録欠測なら、前者を未充足、後者を不明とする。
- 研修受講が完了していても、実務での適用や成果が未測定なら、工程の実施と能力・成果の達成を分ける。
