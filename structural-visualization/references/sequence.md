# 時系列化：プロセスの把握と診断

出典: S01-5（第5章の基本項目 T05.01.01）。原典の要点は [sources.md](sources.md) に記録。以下の形式化・手順・表現選択・評価は PROPOSAL（独自設計）。実践編は未確認。

## 1. 目的と関係を識別する
- 経緯の理解: 何がいつ起きたか。観測された出来事・時点・期間を整理する。
- 工程の理解: どの活動がどの条件で進み、何を次へ渡すか。開始・完了条件と依存を整理する。
- 課題診断: 現状の工程を分解し、根拠のある参照工程・期待状態と照合して、どの工程に改善余地があるかを調べる。
- 計画: これから実行する活動・順序・条件を提案する。予定を実績と混同しない。

時間的前後、手順としての依存、状態の遷移、因果は別の関係。前後関係だけで因果を確定しない。順序が無関係な分類は並列、反復を主題とする場合は円環または複合構造を検討する。

## 2. 工程を分解する
対象・目的・開始と終了の範囲・観測単位を定め、問いに必要な粒度で活動または状態を識別する。各工程は必要に応じてID、活動、実施主体、入力・出力、開始・終了条件、依存先、時刻・期間、状態、根拠を持つ。情報のない属性は不明のまま保持する。

順序が確定した工程だけを直列につなぐ。並行、条件分岐、任意工程、再試行、重なり、不明な順序を区別する。日時のない手順図を時間比例のタイムラインとして描かない。反復は一回の経路と次回への戻りを区別して扱う。

## 3. 参照工程と現状を照合する
参照工程の由来（実績、規程、合意した目標、仮説）と適用条件を明示する。適切な参照工程がなければ現状を先に観測し、参照案は暫定と表示する。現状は記録・観測・申告・推定の区別を保持する。

同じ目的・粒度の工程同士を対応づける。変更、追加、欠落、順序違い、一部実施、分割・統合を区別する。対応関係が不明なら不明と示す。

| 状態 | 判定 |
|---|---|
| 充足 | 根拠により期待条件を満たす |
| 一部充足 | 条件の一部を満たす |
| 未充足 | 条件に反する事実または未実施の根拠がある |
| 不明 | 判定に必要な観測がない |
| 非適用 | 条件分岐などにより当該工程が不要 |

状態の記号・色だけで結論を表現せず、理由を添える。実施の有無と、出力・成果の達成は別に評価する。参照との相違をすべて欠陥とはみなさず、目的への影響を調べる。

## 4. 改善対象と検証を定義する
不足・遅延・手戻り・品質低下等を工程ごとに確認し、全体の成果との関係を仮説として検討する。差異の存在だけで根本原因や律速工程を確定しない。原因候補が複数なら階層化や関係図で補助する。

対策には対象工程、変更する条件・行動、実施時点、実施主体、期待する出力、検証指標を必要に応じて対応づける。改善効果は実施後の観測まで未確認とする。局所改善による他工程への負担移転や全体成果への影響も確認する。

## 5. 最小の表現を選ぶ
| 問い | 表現 |
|---|---|
| 出来事の経緯・時点・間隔 | タイムライン。比例軸には実時刻・期間が必要 |
| 単純な工程の順序 | 番号付き手順、連続工程図 |
| 分岐・並行・依存 | 条件付きフロー、依存関係図、必要に応じ担当別のレーン |
| 参照と現状の差 | 工程IDで対応させた表、または整列した複数の工程列 |
| 改善案と評価 | 課題・対策・指標を対応づけた表、または既存の工程図への注記 |

比較する工程図では共通の工程ID・粒度・範囲を保つ。未知の工程・順序・所要時間・実施状態を図の見栄えのために補わない。順序の説明だけで十分なら図を作らない。
