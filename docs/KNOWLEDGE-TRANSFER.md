# 原典から操作知識への変換

## 取込単位
1. 出典（章・節・電子版位置）と確認範囲を特定する。資料要求はPLAN.mdの目次ID・正式見出しをTOC.mdに照合して行う。見出しと抽出目的を区別し、未確認の見出しを推測で作らない。
2. 著者が定義する対象・関係・成立条件・目的・制約を自分の言葉で簡潔に記録する。目次だけでは本文の主張を確定しない。
3. 独自の操作規則に変換し、原典由来の要約と区別する。
4. 原則を適用する事例・反例を自作する。境界事例、複合事例、図示不要例を含める。
5. 実行時の指示に組み込み、出典台帳と評価ケースを更新する。

## 1構造の記録様式

| フィールド | 記録内容 |
|---|---|
| ID | parallel / hierarchy / matrix / sequence / cycle |
| 原典 | 章・節・位置、確認状態 |
| 定義 | 関係の種類 |
| 認知目的 | 読者が答えられる問い |
| 入力 | 対象・属性・関係・根拠 |
| 成立条件 | 適用できる必要条件 |
| 操作規則 | 入力から出力への判断手順 |
| 表現候補 | 最小の文章・表・図の選択肢 |
| 非適用・反例 | 誤解・過剰表現を招く状況 |
| 合成 | 他構造と組み合わせる条件 |
| 検証 | 正例・負例・評価方法 |

状態: TOC（目次のみ）、SOURCE（本文確認済みの要約）、PROPOSAL（独自設計）、TESTED（検証済み）。出典確認と実用性検証は別々に管理する。

## 役割
- ユーザー: 所有する電子書籍の指定箇所を確認し、必要部分または要点を共有。原典との整合性・理解のしやすさを確認。
- ChatGPT: 共有範囲の読解、要約、独自の操作規則・例・反例への変換、GitHubへの記録、差分検証。

公開物は原典の代替にならない独自の操作知識に限定する。書籍本文・図表画像・長い引用はリポジトリに転載しない。必要な参照位置と書誌情報を保持する。

## セッションの終了と再開
各回の作業は原典確認・操作規則・評価仕様・進捗の一貫したコミットで完結させる。次回のチャットで過去の会話を読み直す前提にしない。PLAN.md のチェックポイントに、確認範囲、実装済みの変更、未検証事項、次に依頼する原典箇所（目次ID・正式見出しのキュー）、関連PRを記録する。目次台帳との照合を終了条件とする。再開時は RESUME.md に従って実際のGitHub状態を照合する。
