# 操作知識の設計と改訂

## 目的

個別の説明や事例を、異なる領域でも適用できる判断手順へ変換する。固有の表現を言い換えるだけで済ませず、適用条件・反例・終了条件を定める。

## 手順

1. 読者の問い、対象、関係、成立条件を切り出す。
2. 事実・定義・仮説・設計上の選択を区別する。未確認の因果や数値を補わない。
3. 「どんな入力で、何を確認し、何を選び、どこで止めるか」の操作規則にする。
4. 領域の異なる独自例、失敗例、境界例、図を作らない例を用意する。
5. 実行時の短い入口と、必要時だけ読む詳細参照に分ける。資料の要約順や章立てをそのまま構造にしない。
6. 評価入力だけを渡した独立実行で確かめ、実際の出力を評価基準と照合する。
7. 変更した規則と結果を記録し、検証範囲を越える効果を主張しない。

## 記録する項目

| 項目 | 内容 |
|---|---|
| 対象 | どんな問い・情報に使うか |
| 入力 | 必要な対象・属性・関係・根拠 |
| 操作 | 条件に応じた選択、変換、検査 |
| 出力 | 保持すべき情報と適した表現 |
| 境界 | 使わない条件、代替表現、不明時の対応 |
| 終了 | 問いへ答え、重要な例外が保持された状態 |
| 検証 | 入力、出力、実施条件、判定、未確認事項 |

過去の資料確認記録は `docs/archive/` を参照する。追加資料が必要な場合は確認範囲を限定し、未確認の内容を読了扱いにしない。配布物は自立した操作知識に限定し、資料本文・図版・画像を転載しない。
